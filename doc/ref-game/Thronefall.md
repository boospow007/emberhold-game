# Thronefall — เอกสารทำความเข้าใจเกมเพื่อใช้อ้างอิง

- ผู้พัฒนา: GrizzlyGames (Jonas Tyroller และ Paul Schnepf) เยอรมนี ทีม 2 คน
- ออก Early Access บน Steam: สิงหาคม 2023 · เวอร์ชัน 1.0: ตุลาคม 2024
- แพลตฟอร์ม: PC เป็นหลัก มีเวอร์ชันมือถือ/คอนโซลตามมา
- แนวเกม: Minimalist strategy / tower defense + action ควบคุมกษัตริย์ตัวเดียว
- จุดขาย: RTS ที่ตัดทุกอย่างเหลือ "วางของตอนกลางวัน สู้ตอนกลางคืน" ด่านละ 20–30 นาที ควบคุมด้วยปุ่มไม่กี่ปุ่ม กราฟิก low-poly สะอาดตา
- ความเกี่ยวข้อง: เป็นเกมที่ **ใกล้ Emberhold ที่สุด** ในบรรดาเกมอ้างอิง ทั้งวงจร prep/battle, ฮีโร่ตัวเดียวในสนาม, สิ่งก่อสร้างอัปเกรดในที่เดิม และการมองจากมุมสูง

> จุดประสงค์ของเอกสารนี้คือถอดแก่นของเกมมาเป็นข้อมูลอ้างอิงสำหรับออกแบบ Emberhold ไม่ใช่คู่มือเล่นเกม

---

## 1. Core loop

```
กลางวัน: รับรายได้ → เดินไปจุดก่อสร้าง → กดสร้าง/อัปเกรด → ดูตัวอย่าง wave คืนนี้
กลางคืน: ศัตรูบุกจากทิศที่บอกไว้ → กษัตริย์สู้ร่วมกับทหาร → รอดถึงเช้า
→ วนซ้ำจนครบจำนวนคืนของด่าน → ชนะ
```

แต่ละด่านมีจำนวนคืนตายตัว (ราว 10–15 คืน) คืนสุดท้ายเป็น wave ใหญ่สุด ชนะเมื่อรอดครบ แพ้เมื่อ **ปราสาทถูกทำลาย**

## 2. การควบคุม

- เดินด้วยสติ๊ก/WASD, โจมตี 1 ปุ่ม, เรียกทหารตาม 1 ปุ่ม, สร้าง/อัปเกรดคือเดินไปยืนที่จุดแล้วกดยืนยัน
- **ไม่มีเคอร์เซอร์ ไม่มีเมนูซ้อน ไม่มีการเลือกหน่วยเป็นกลุ่ม** ทุกอย่างทำผ่านตัวกษัตริย์ในโลก
- กษัตริย์ขี่ม้าเร็ว ใช้เป็นทั้งผู้สร้าง ผู้บัญชาการ และ DPS
- ทหารจะ **ตามกษัตริย์** เมื่อกดเรียก และกลับไปประจำที่เมื่อปล่อย ทำให้ย้ายกำลังพลได้โดยไม่ต้องลากกรอบ

## 3. เศรษฐกิจ

- ทรัพยากรเดียวคือ **เหรียญทอง**
- ทองออกมาเป็น **เหรียญจริงบนพื้น** ตอนเช้าจากบ้าน/ฟาร์ม/โรงสี และตกจากศัตรูที่ตาย ต้องเดินไปเก็บ
- ราคาสิ่งก่อสร้างแสดงเป็นเหรียญที่ต้อง "ยืนจ่าย" ทีละเหรียญ (กดค้าง) ทำให้การใช้เงินมีน้ำหนักและมองเห็น
- รายได้โตตามอาคารเศรษฐกิจ ผู้เล่นต้องเลือกระหว่างลงทุนเศรษฐกิจตอนต้น (เสี่ยงคืนแรกๆ) หรือป้องกันก่อน (โตช้า)

## 4. จุดก่อสร้างแบบกำหนดไว้ (Fixed build slots)

การตัดสินใจออกแบบที่สำคัญที่สุดของเกม:
- แต่ละด่านมี **จุดก่อสร้างที่ผู้พัฒนาวางไว้ล่วงหน้า** จะสร้างอะไรได้แค่ในจุดนั้น
- แต่ละจุดกำหนดชนิดไว้แล้ว (จุดนี้เป็นหอคอย จุดนี้เป็นกำแพง จุดนี้เป็นบ้าน)
- ผู้เล่นเลือกแค่ **ลำดับ** ที่จะสร้าง และ **สาย** ที่จะอัปเกรด
- ผลคือ: ไม่มีปัญหา placement บนจอเล็ก, ผู้พัฒนาปรับสมดุลได้แม่น, ด่านมีคาแรกเตอร์ชัด, แต่ลดความสร้างสรรค์ของผู้เล่น

## 5. สิ่งก่อสร้างและการอัปเกรด

| ประเภท | ตัวอย่าง | หมายเหตุ |
|---|---|---|
| เศรษฐกิจ | บ้าน, ฟาร์ม, โรงสี, เหมือง | ให้ทองตอนเช้า |
| ป้องกัน | กำแพง, ประตู, หอคอยธนู, บัลลิสตา, ปืนใหญ่ | มีเลือดและซ่อมได้ |
| ทหาร | ค่ายทหาร (militia), ค่ายธนู, นายพราน, อัศวิน | ทหารเกิดใหม่ตอนเช้าถ้าตาย |
| ปราสาท | ศูนย์กลาง | อัปเกรดเพิ่มเลือดและปลดล็อกจุดสร้างใหม่ |

**การอัปเกรด**
- ทุกอาคารอัปเกรด **ในที่เดิม** และส่วนใหญ่มีทางแยกให้เลือก 1 ใน 2 เช่น หอคอยธนู → ยิงไกล หรือ ยิงไฟ; กำแพง → หนา หรือ มีหนาม
- ทางแยกเลือกแล้วเลือกใหม่ไม่ได้ (ในด่านนั้น) ทำให้เป็นการตัดสินใจจริง
- อัปเกรดปราสาทมักเป็นตัวปลดล็อกจุดก่อสร้างรอบนอกเพิ่ม ฐานจึงขยายเป็นวง

## 6. ศัตรูและ wave

- ก่อนกลางคืนเกมแสดง **ตัวอย่าง wave**: ชนิดศัตรู จำนวนโดยประมาณ และ **ทิศทางที่มา** (ไอคอนบนขอบแผนที่)
- ศัตรูมีหลายชนิดที่ counter การป้องกันคนละแบบ เช่น
  - ทหารราบทั่วไป: ตีกำแพง
  - นักธนู: ยิงข้ามกำแพงใส่ทหารบนหอ
  - หมาป่า: เร็ว วิ่งอ้อมกำแพงไปหาบ้าน
  - ยักษ์/โอเกอร์: ทุบกำแพงพังเร็ว
  - เครื่องยิงหิน: อยู่ไกล ยิงอาคาร ต้องออกไปฆ่า
  - มังกร/หน่วยบิน: ข้ามกำแพง ต้องมีหอคอยยิงบน
- ศัตรูมีเป้าหมายเป็น **อาคาร** ไม่ใช่ผู้เล่น จะโจมตีผู้เล่นเมื่อถูกขวางหรือถูกตี
- ศัตรูมาจาก **หลายทิศพร้อมกัน** ในคืนหลังๆ บังคับให้แบ่งกำลัง

## 7. กษัตริย์ (ตัวผู้เล่น)

- เลือก **อาวุธ** ก่อนเริ่มด่าน (ดาบ, หอก, ธนู, ค้อน ฯลฯ) แต่ละอย่างเปลี่ยนสไตล์ (ระยะ, กลุ่ม, เดี่ยว)
- เลือก **perk** ได้จำนวนจำกัด (ปลดล็อกจากการเล่น) เช่น ทหารเลือดเพิ่ม, กษัตริย์ฟื้นเลือด, ทองเพิ่ม
- ถ้ากษัตริย์ตายในคืนนั้นจะ **ฟื้นที่ปราสาทเมื่อถึงเช้า** ไม่จบเกม แต่คืนนั้นเสียกำลังหลักไป
- กษัตริย์ไม่ใช่ตัวแบก ทหารและหอคอยคือ DPS หลัก กษัตริย์คือ "ตัวอุดรูรั่ว" และ "ตัวย้ายทหาร"

## 8. Meta-progression และความยาก

- **ปลดล็อกอาวุธและ perk** จากการผ่านด่านหรือทำภารกิจย่อย
- **Mutators / Modifiers** ก่อนเริ่มด่าน: เปิดเพื่อเพิ่มความยากแลกคะแนน เช่น ศัตรูเลือดเพิ่ม 50%, ไม่มีการซ่อม, กษัตริย์ไม่ฟื้น ผู้เล่นผสมเองได้
- คะแนนต่อด่านและ leaderboard เป็นแรงจูงใจให้เล่นซ้ำ ไม่ใช่ endless
- ด่านทั้งหมดมีจำนวนไม่มาก (ราว 8–10 ด่าน) แต่ละด่านต่างกันที่แผนที่และจุดสร้าง ไม่ใช่สุ่ม

## 9. กลไกที่ทำให้เกมนี้โดดเด่น

### 9.1 ตัดทุกอย่างเหลือแก่น
ไม่มี tech tree ไม่มีทรัพยากรหลายชนิด ไม่มีการเลือกหน่วย ผู้เล่นเข้าใจทั้งเกมใน 2 นาทีแรก แต่การตัดสินใจ "สร้างอะไรก่อน" ยังลึกพอ

### 9.2 ทุกอย่างทำผ่านตัวละครในโลก
การสร้างต้องเดินไป การจ่ายเงินต้องยืนจ่าย การย้ายทหารต้องเดินนำ ทำให้การเคลื่อนที่ของกษัตริย์คือทรัพยากรที่ต้องบริหาร (ไปสร้างฝั่งซ้ายแปลว่าไม่ได้ป้องกันฝั่งขวา)

### 9.3 ข้อมูลครบก่อนตัดสินใจ
รู้ทิศทาง รู้ชนิด รู้จำนวนคร่าวๆ ของ wave ถัดไป ความยากจึงมาจาก "ทรัพยากรไม่พอทำทุกอย่าง" ไม่ใช่ "ไม่รู้ว่าจะโดนอะไร"

### 9.4 อัปเกรดแบบทางแยก
ทุกอาคารมีทางเลือก 2 ทางที่ต่างกันจริง ทำให้ฐานของผู้เล่นแต่ละคนต่างกันแม้จุดสร้างจะเหมือนกัน

### 9.5 คืนสั้น กลางวันสั้น
รอบ day/night ยาวราว 1–2 นาที ไม่มีช่วงรอ ผู้เล่นตัดสินใจตลอดเวลา

### 9.6 ความสวยจากความน้อย
กราฟิก low-poly สีเรียบ ไม่มี HUD ทับจอ ตัวเลขทั้งหมดแสดงในโลก (เหรียญ, ป้ายราคา, ไอคอน wave) ทำให้จอเล็กยังอ่านได้

## 10. จุดอ่อน / คำวิจารณ์ที่ควรรู้
- เนื้อหาน้อย จบได้ใน 5–8 ชั่วโมง ถ้าไม่สนคะแนน
- จุดสร้างตายตัวทำให้แต่ละด่านมี "คำตอบ" ที่ค่อนข้างชัดหลังเล่นสองสามรอบ
- คืนหลังๆ ของบางด่านศัตรูมาหลายทิศจนกษัตริย์ทำอะไรไม่ทัน กลายเป็นเกม "วางให้ถูกตั้งแต่กลางวัน" ล้วนๆ
- ไม่มีโหมด endless ผู้เล่นที่ชอบ scaling ยาวๆ จะไม่พอ
- อาวุธและ perk บางอย่างแรงกว่าชิ้นอื่นชัดเจน

## 11. สิ่งที่ Emberhold นำมาใช้ได้ (และสิ่งที่ไม่ควร)

Emberhold มีโครงเหมือน Thronefall อยู่แล้วหลายอย่าง: prep/battle, ฮีโร่ในสนาม, ทองอย่างเดียว, อัปเกรดในที่เดิมแบบมีสาย (`upgrade` พร้อม `branch`), ฟาร์มให้รายได้หลัง wave, แพ้เมื่อ keep พัง สิ่งที่ต่างคือ Emberhold วางอิสระ เป็น endless และ co-op online

### ควรนำมาใช้
| แนวคิดจาก Thronefall | ปรับใช้กับ Emberhold |
|---|---|
| ตัวอย่าง wave ก่อนคืน | ช่วง prep แสดงไอคอนชนิดศัตรู จำนวน และทิศทางที่ขอบจอ เป็นสิ่งที่ควรทำเป็นอันดับแรก เพราะทำให้ prep phase มีความหมาย |
| ศัตรูมีเป้าหมายเป็นอาคาร | ยืนยันว่า AI ศัตรูของ Emberhold มุ่งไป keep/อาคาร และหันมาตีผู้เล่นเฉพาะเมื่อถูกขวาง ไม่ใช่วิ่งหาผู้เล่น |
| ศัตรูหลายทิศพร้อมกัน | หลัง wave 5+ ให้แบ่งจุดสปอว์นเป็น 2–3 ทิศ เพื่อให้ co-op 4 คนต้องแบ่งกันคุม ไม่ใช่กองรวมจุดเดียว |
| ทองเป็นเหรียญบนพื้น | Emberhold มีคริสตัลที่ต้องเก็บแล้ว อาจแยก "ทองจากศัตรู" ให้ตกบนพื้นเช่นกัน แล้วให้ทองเข้ากองกลางของทีมเมื่อใครก็ได้เก็บ ทำให้การเดินมีค่า |
| ทางแยกอัปเกรด 2 ทาง | มี `branch` แล้ว ตรวจให้ทุกสิ่งก่อสร้างมีอย่างน้อย 2 สายที่ต่างกันจริง (ระยะ vs กลุ่ม, เลือด vs หนาม) และเลือกแล้วเปลี่ยนไม่ได้ |
| อัปเกรด keep ปลดล็อกพื้นที่ | ให้การอัปเกรด keep ขยายรัศมีที่สร้างได้ ทำให้ฐานโตเป็นวงและมีเป้าหมายกลางรอบ (ตอนนี้ `canBuild` ใช้กฎภูมิประเทศอย่างเดียว) |
| Mutators ก่อนเริ่ม | เหมือน Curse ใน Vampire Survivors ให้เปิดได้หลายตัวพร้อมกัน คูณ Ember ตามจำนวนที่เปิด |
| ฮีโร่ตายแล้วฟื้นที่ keep | Emberhold ฟื้นใน 8 วินาทีอยู่แล้ว อาจปรับให้ฟื้นเร็วขึ้นตอน prep และช้าลงตอน battle |
| HUD ในโลก | แสดงราคาและชื่อสิ่งก่อสร้างลอยเหนือตำแหน่ง แทนแผงเมนู ลด UI ทับจอแนวตั้ง |
| ทหารตามฮีโร่ | ถ้าในอนาคตมีหน่วยทหาร ให้ใช้ปุ่มเดียว "ตามฉัน/กลับที่" แทนการเลือกหน่วย |

### ไม่ควรนำมาใช้ตรงๆ
- จุดสร้างตายตัว: Emberhold เลือกวางอิสระแล้ว และเป็นข้อได้เปรียบใน co-op (ผู้เล่นแต่ละคนสร้างโซนของตัวเอง) แต่ควรพิจารณา **ลูกผสม**: มีจุดแนะนำที่ให้โบนัส (เช่น หอคอยบนเนินยิงไกลขึ้น) เพื่อได้ความชัดของ Thronefall โดยไม่เสียอิสระ
- จำนวนคืนตายตัวและชนะได้: Emberhold เป็น endless ไม่ควรมี "ชนะ" แต่ควรมีจุดหมายย่อย (boss wave, milestone ทุก 5 wave)
- ยืนจ่ายเหรียญทีละเหรียญ: ใช้เวลาและต้องกดค้าง ไม่เหมาะกับหน้าจอสัมผัสมือเดียวที่นิ้วเดียวใช้เดินอยู่แล้ว
- ทุกอย่างต้องเดินไปทำ: ใน co-op ที่ host จำลองและ guest มี latency การบังคับให้เดินไปสร้างจะเจ็บกว่าบน PC ปัจจุบัน Emberhold ให้สร้างจากระยะไกลได้แต่ต้องเดินไปอัปเกรด ซึ่งเป็นจุดกลางที่ดีอยู่แล้ว

### คำถามออกแบบที่ยังเปิดอยู่
1. ระบบ preview wave ต้องการข้อมูลอะไรจาก `startWave` และควรเก็บใน `World` เพื่อให้ guest เห็นผ่าน snapshot อย่างไร
2. ควรมี "จุดแนะนำ" ที่ให้โบนัสบนแผนที่หรือไม่ และจะแสดงบนจอเล็กอย่างไรโดยไม่รก
3. ทองกองกลางของทีมพอหรือไม่ หรือควรมีทองส่วนตัวสำหรับ perk ของแต่ละคน
